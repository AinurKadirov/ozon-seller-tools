# Ozon — управление магазином

Набор скриптов для ежедневного контроля доходности магазина на Ozon: считают
P&L, выставляют цены под целевую прибыль, выводят из убыточных акций и блокируют
авто-снижение цен Ozon.

---

## TL;DR — вечерний ритуал

Каждый вечер запускай по порядку:

```bash
# 1. Посмотреть, что было сегодня и вчера + прибыль по каждому товару (в Telegram)
npm run ozon:daily-report

# 2. Проверить акции и выйти из убыточных
npm run ozon:monitor-promos

# 3. Снять авто-флаги, если Ozon включил их обратно
npm run ozon:disable-auto-actions          # посмотреть
npm run ozon:disable-auto-actions -- --apply  # применить

# 4. Снять снапшот SEO-позиций (копит тренд в MongoDB)
npm run ozon:track-seo
```

Раз в неделю (например, в воскресенье):

```bash
npm run ozon:weekly-report                 # сводка за 7 дней в Telegram
npm run ozon:ads-analysis -- 7             # что в рекламе резать/масштабировать (id РК)
npm run ozon:unit-economics 30             # фактические ставки и мин. цены по SKU
npm run ozon:seo-trend                     # как менялись позиции в поиске
npm run ozon:set-prices-150                # посмотреть, нужно ли поднять цены
npm run ozon:set-prices-150 -- --apply     # применить новые цены
```

## Скрипты

| Команда | Назначение | По умолчанию | Telegram |
|---|---|---|---|
| `ozon:daily-report` | Доходность по дням + прибыль по каждому товару | отправляет | да |
| `ozon:weekly-report` | Доходность за 7 дней (одна сводка) | отправляет | да |
| `ozon:ads-analysis` | Анализ РК: ДРР факт vs безубыток, id кампаний, кандидаты | отправляет (30 дн.) | да |
| `ozon:unit-economics` | Фактические ставки по SKU + мин. цена под цель прибыли | только консоль (15 дн.) | нет |
| `ozon:set-prices-150` | Цены под +150 ₽/шт, min_price = безубыток | **DRY** (только показ) | нет |
| `ozon:monitor-promos` | Выход из убыточных акций | выходит + отправляет | да |
| `ozon:disable-auto-actions` | Полностью запретить авто-участие в акциях | **DRY** (только показ) | нет |
| `ozon:enable-safe-auto-actions` | Авто-участие в акциях с полом цены (прибыль защищена) | **DRY** (только показ) | нет |
| `ozon:track-seo` | Снапшот позиций в поиске → MongoDB | пишет снапшот | нет |
| `ozon:seo-trend` | Тренд позиций по фразам из снапшотов | только консоль | нет |
| `ozon:supply-plan` | План поставки FBO по кластерам + XLSX для загрузки | пишет XLSX | нет |

### Соглашение по флагам

- **Скрипты-отчёты** (`daily`, `weekly`) и `monitor-promos` по умолчанию **действуют**
  (отправляют в Telegram / выходят из акций). Для `monitor-promos` флаг `--dry` —
  безопасная проверка: без выхода из акций, но с отправкой в Telegram.
- **Скрипты, меняющие цены** (`set-prices-150`, `disable-auto-actions`) по умолчанию
  работают в **DRY-режиме** (безопасный предпросмотр). Флаг `--apply` — применить изменения.

```bash
npm run ozon:weekly-report -- --dry        # отчёт без отправки
npm run ozon:monitor-promos -- --dry       # показать убыточные акции, не выходя (отчёт отправится в Telegram)
npm run ozon:set-prices-150 -- --apply     # реально обновить цены
npm run ozon:set-prices-150 -- 200         # цель +200 ₽/шт вместо 150
npm run ozon:daily-report -- 2026-06-01 2026-06-02   # конкретные даты
```

## Кто за что отвечает

```
1. daily / weekly report  →  «сколько я заработал/потерял»
2. set-prices-150         →  «по какой цене продавать, чтобы быть в плюсе»
3. monitor-promos         →  «не торгую ли я в минус из-за акций»
4. disable-auto-actions   →  «запретить Ozon самому снижать мои цены»
```

Логичная последовательность при настройке с нуля:
**set-prices-150 → (disable | enable-safe) auto-actions → monitor-promos → daily/weekly report**.

### Участие в акциях: два взаимоисключающих режима

`disable-auto-actions` и `enable-safe-auto-actions` — это две противоположные
стратегии. Запускай **что-то одно**:

- **`disable-auto-actions`** — полный ручной контроль. Ozon не трогает цены и не
  добавляет товары в акции вообще. В акции вступаешь только вручную.
- **`enable-safe-auto-actions`** — авто-участие с защитой. Ozon добавляет товары
  в акции автоматически, но `min_price` работает как пол: цену ниже него не
  опустят. В акции, требующие цену ниже пола, тебя не добавят.

  Пол = цена целевой прибыли (по умолчанию +150 ₽/шт):
  ```bash
  npm run ozon:enable-safe-auto-actions              # показать
  npm run ozon:enable-safe-auto-actions -- --apply   # включить (пол +150 ₽/шт)
  npm run ozon:enable-safe-auto-actions -- 0 --apply # пол = безубыток (больше участия)
  ```

  **Текущий режим магазина: `enable-safe-auto-actions` с полом +150 ₽/шт.**
  При нём `monitor-promos` становится подстраховкой — на случай, если какая-то
  акция всё же проскочит ниже пола.

## Анализ рекламы (`ozon:ads-analysis`)

Тянет кампании из Ozon Performance API, считает по каждому SKU маржу до рекламы
(→ «безубыточный ДРР») и сравнивает с фактическим ДРР. Делит товары на три группы:
что крутится (масштабировать/держать/резать), что выключено (можно включить),
кандидаты на добавление (продаются органически, но не в РК).

```bash
npm run ozon:ads-analysis              # 30 дней + Telegram
npm run ozon:ads-analysis -- 7         # за 7 дней (совпадает с кабинетом)
npm run ozon:ads-analysis -- 7 --dry   # только консоль
```

**ДРР считается по ПРЯМЫМ рекламным заказам** (`расход / ordersMoney`) — ровно как
в кабинете Ozon, а не по обороту товара. Рядом в скобках показывается «с моделью %» —
мягкий вариант с модельной атрибуцией. Если есть расход, но 0 прямых заказов → ДРР `∞`
и вердикт «выключить».

Под каждым товаром выводится **id рекламной кампании**, её название и состояние
(`РК 21405336 «Бежевый оплата за клик» (активна)`) — и в консоли, и в Telegram.

Требует креды Performance API в `.env.development`:
`OZON_PERFORMANCE_CLIENT_ID`, `OZON_PERFORMANCE_CLIENT_SECRET`.

## Юнит-экономика (`ozon:unit-economics`)

Считает фактические ставки комиссии / логистики / эквайринга из реальных транзакций
по каждому SKU и выводит минимальную цену под заданную целевую прибыль.

```bash
npm run ozon:unit-economics             # последние 15 дней
npm run ozon:unit-economics 30          # 30 дней
npm run ozon:unit-economics 15 100 200  # 15 дней, цели прибыли 100 и 200 ₽/шт
```

## SEO-позиции (`ozon:track-seo`, `ozon:seo-trend`)

`track-seo` снимает снапшот позиций моих товаров в поиске Ozon по списку ключевых
фраз и пишет в MongoDB (коллекция `seo_rank_snapshots`). Запускай регулярно
(например, ежедневно), чтобы копился тренд. `seo-trend` показывает динамику.

```bash
npm run ozon:track-seo                          # разовый снапшот
npm run ozon:track-seo -- --raw                 # + сырой ответ API первой фразы

npm run ozon:seo-trend                          # последние 10 снапшотов
npm run ozon:seo-trend -- --phrase "фотоальбом" # только одна фраза
npm run ozon:seo-trend -- --n 20                # последние 20 снапшотов
npm run ozon:seo-trend -- --since 2026-06-01    # с даты
```

> ⚠️ Куки протухают. При 401/403 обнови `OZON_SELLER_COOKIES` в `.env.development`
> (DevTools → Network на seller.ozon.ru → заголовок Cookie любого XHR).

## Поставки FBO по кластерам (`ozon:supply-plan`)

Считает, сколько каждого альбома и в какой кластер Ozon довезти, и генерирует
готовые XLSX для загрузки при создании поставки (формат шаблона импорта Ozon:
`артикул | имя | количество`).

```bash
# план + 8 файлов в ~/Desktop/ozon-supply (рядом с выгрузкой)
npm run ozon:supply-plan -- "~/Desktop/export_all_items (4).xlsx"

# только показать план, без файлов
npm run ozon:supply-plan -- "<stock.xlsx>" --no-files

# свои параметры: запас 60 дней, окно продаж 14 дней, 5 кластеров, своя папка
npm run ozon:supply-plan -- "<stock.xlsx>" --cover 60 --days 14 --hubs 5 --out ~/postavka
```

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--cover N` | целевой запас в днях | 45 |
| `--days N` | окно для оценки скорости продаж | 30 |
| `--hubs N` | в сколько верхних кластеров везём | 8 |
| `--out DIR` | куда складывать XLSX | `<папка stock.xlsx>/ozon-supply` |
| `--no-files` | только план в консоль | — |

**Что на входе:** путь к выгрузке остатков склада в Москве из 1С/Ozon
(колонки «Артикул» и «Остаток свободный»).

**Как считает:**
1. `target = скорость_продаж × cover`, `везём = max(0, target − остаток_FBO)`,
   но не больше, чем есть на складе в Москве.
2. Распределяет по топ-`hubs` кластерам пропорционально их доле в текущих
   остатках FBO (метод наибольшего остатка для целых чисел).

> ⚠️ **Прокси по регионам.** Ozon больше не отдаёт продажи в разрезе регионов
> через API, поэтому спрос по кластерам оценивается по доле кластера в остатках
> FBO (где товар уже разложен — там и продаётся). Это оценка, не точные
> региональные продажи: сверяйтесь со здравым смыслом перед отправкой.

Требует у API-ключа роль **«Аналитика»** (остатки по складам, скорость продаж,
список кластеров).

## Финансовая модель

Все формулы и ставки — в [`lib/economics.ts`](./lib/economics.ts).

```
COMM_RATE = 0.46   комиссия Ozon
TAX_RATE  = 0.07   УСН «доходы» 7% (Москва)
NET_RATE  = 0.47   = 1 − 0.46 − 0.07  (остаётся с рубля цены)

Цена  = (Себестоимость + ФиксРасходы + ЦельПрибыли) / NET_RATE
Безубыток = Цена при ЦельПрибыли = 0
```

**ФиксРасходы** = логистика + эквайринг + реклама на единицу (≈ 240–410 ₽,
из реальных транзакций). P&L отчётов считается напрямую из транзакций Ozon
(`/v3/finance/transaction/list`), а не по этим средним.

## Где менять данные

**Себестоимость и расходы — только в [`lib/catalog.ts`](./lib/catalog.ts).**
Это единый источник: измени цифру там, и её увидят все скрипты. Раньше эти
таблицы дублировались в каждом файле и расходились — теперь нет.

```ts
{ offerId: 'DEMO-001', sku: 1000000001, cost: 500, fixed: 250, name: 'Sample album', group: 'АБ' }
```

**Роли API-ключа Ozon:**
- «Товары и цены» — для `set-prices-150`, `disable-auto-actions`
- «Акции» — для выхода из акций в `monitor-promos`
- «Аналитика» — для остатков и скорости продаж в `supply-plan`
- Performance API — отдельные креды (client_id/secret) для `ads-analysis`

## Частые вопросы

**Почему все товары были убыточны?** Комиссия 46% + налог 7% = 53% уходит сразу.
Плюс участие в акциях снижало фактическую цену ниже безубытка. Решение:
поднять цены (`set-prices-150`), выйти из акций (`monitor-promos`),
заблокировать авто-снижение (`disable-auto-actions`).

**Меня будут добавлять в прибыльные акции?** Да, если включён
`enable-safe-auto-actions` (текущий режим). Ozon добавит товар только в акции,
где цена остаётся ≥ пола (+150 ₽/шт прибыли). В убыточные — не добавит.
Если хочешь полностью отключить авто-участие — запусти `disable-auto-actions -- --apply`.

**Ozon сбрасывает настройки авто-акций.** Это бывает (~раз в 30 дней). Просто
перезапусти выбранный скрипт (`enable-safe-auto-actions -- --apply` или
`disable-auto-actions -- --apply`). Можно повесить в cron.

**Цифры daily и weekly совпадают?** Да — оба используют один расчёт
`computeDayPnl` из `lib/economics.ts`.
